<!-- Target updateItem handler (cart.controller.ts) -->

```
@Patch('items/:id')
@ApiOperation(...)
async updateItem(
  @GetUser() user: User,
  @Param('id', ParseIntPipe) itemId: number,
  @Body() dto: UpdateCartItemDto,
  @Res({ passthrough: true }) res: Response,    // express Response, passthrough so interceptor still runs
) {
  const result = await this.cartService.updateItemQuantity(user.id, itemId, dto);
  if (result === undefined) {
    res.status(HttpStatus.NO_CONTENT);
    return;   // interceptor sees statusCode=204 and returns undefined → empty body
  }
  return result;
}
```

<!-- Why Option C (and not @HttpCode(204)) -->

A single handler cannot statically return both 200 and 204 via a `@HttpCode()` decorator. `@Res({ passthrough: true })` keeps Nest's normal serialization pipeline active (so the interceptor still fires) while letting the handler dynamically set the status code. The Plan 01 interceptor bypass then strips the body for the 204 path.
