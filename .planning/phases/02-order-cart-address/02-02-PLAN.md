## Trust Boundaries

| Boundary                           | Description                                                                      |
| ---------------------------------- | -------------------------------------------------------------------------------- |
| HTTP client → AddressController    | Untrusted user input (DTO fields, path UUID) crosses here                        |
| AddressController → AddressService | Authenticated `user.id` from JWT crosses; ownership scoping enforced server-side |
| AddressService → PrismaService     | Transactional mutation crosses; atomicity boundary for isDefault toggle          |

## STRIDE Threat Register

| Threat ID | Category               | Component                     | Disposition | Mitigation Plan                                                                                                                                                                                                                              |
| --------- | ---------------------- | ----------------------------- | ----------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| T-02-04   | Spoofing               | AddressController route entry | mitigate    | Class-level `@UseGuards(JwtAuthGuard)` per D-04 — no anonymous access; `userId` is sourced exclusively from the verified JWT via `@GetUser()`, never from request body or params.                                                            |
| T-02-05   | Tampering              | DTO input validation          | mitigate    | `class-validator` decorators (`@IsString`, `@IsBoolean`, `@MaxLength`, `@IsOptional`) on every CreateAddressDto field; UpdateAddressDto via `PartialType` inherits the same. `ParseUUIDPipe` on `:id` rejects non-UUID path params with 400. |
| T-02-06   | Repudiation            | Address mutations             | accept      | Out of scope — no audit log requirement in this phase; Prisma `createdAt`/`updatedAt` columns already capture timestamps.                                                                                                                    |
| T-02-07   | Information Disclosure | Cross-user address read       | mitigate    | `findOwnedAddress` private helper enforces `address.userId === requestingUserId` before any update/delete; `findAll` filters by `where: { userId }`. Mismatch → `ForbiddenException` (403). Non-existent id → `NotFoundException` (404).     |
| T-02-08   | Denial of Service      | Unbounded `findAll`           | accept      | Per-user address lists are bounded (typical user has 1-10 addresses); no pagination needed in this phase per SPEC.                                                                                                                           |
| T-02-09   | Elevation of Privilege | isDefault flag manipulation   | mitigate    | `isDefault` toggle is restricted to the requesting user's own addresses via `updateMany({ where: { userId, isDefault: true } })` — cannot affect other users; ownership guard prevents PATCH on someone else's address.                      |
| T-02-10   | Tampering              | Atomic default-toggle race    | mitigate    | The unset+set sequence is wrapped in `prisma.$transaction(async (tx) => { ... })` — no intermediate state where two addresses are both `isDefault=true` for the same user; READ COMMITTED isolation is sufficient per D-07.                  |
| T-02-11   | Data Integrity         | Delete of default address     | mitigate    | `remove()` throws `BadRequestException('Cannot delete the default address')` when `address.isDefault === true`, preventing the user from being left in a state with zero defaults via an explicit deletion.                                  |

</threat_model>
